# Overview reminder groups

The Overview shows the events of one day as reminder groups. A reminder group holds the reminder events that share one reminder timestamp, and it renders as one card. A group of two or more events has a time header above the card. A one-event group has no header, because its state button and long-press already offer every action that a header would offer. The group key is exact timestamp equality, through `groupBySameTime` in `:feature:reminders:api`. A tolerance window was considered and rejected. A merged notification records its anchor instant on every member, so exact equality keeps the Overview group, the notification and the recorded history in agreement. A window would split a merged notification across two cards and break the `reminderId to remindedTimestamp` dedup key in `OverviewViewModel.getFiltered`. Grouping has its own setting, `group_overview_events`, which is on by default. It is independent of `combine_notifications`, which only combines notifications and stays off by default. With the grouping setting off, every event forms its own group. Long-press selection follows the same setting, so a long press selects the group that the card shows.

Each event stays its own lazy list item, and the first item of a group with two or more events draws the group header. Without a header, the item of a one-event group carries the spacing between groups itself. `OverviewTestTags.group` keeps the absolute group index, so the header tags can skip the numbers of one-event groups. The rows of one group round only their outer corners, so the group reads as one card. A single lazy item per group was rejected because `OverviewRobot` scrolls by lazy item index and addresses rows through the running index of `OverviewTestTags.event`. The state button stays outside the card on the left, and the rail keeps drawing from the button centers. Inside a group, the rail shrinks its inset so that a short pill still links the rows. The events of one time sort by reminder and then by event id, so a dose keeps its row when it is taken and gets a new, smaller event id.

Long-press selection mode stays beside the new header. The header adds `Confirm all` and an overflow menu. Both derive from `MultipleActions`, so the header never offers more than the selection bar offers for the same events. `Confirm all` marks only the unresolved events of a group taken, so a part-resolved group keeps the times that were already logged.
